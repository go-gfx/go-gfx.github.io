Pure Go CGO=0 Zero dependencies 6 architectures BSD-3-Clause

Why go-gfx

2D graphics in most languages means binding a C engine — Skia, Cairo, Pixman. Across the Go fleet, several libraries had each grown their own copy of the same primitives: an image processor resampling pixels, a widget toolkit rasterizing vector paths, a web engine decoding image codecs, a desktop stack rendering icons. go-gfx extracts that shared substrate into one pure-Go, cgo-free module so colour blending, resampling, codecs and path rasterization are written and tested once. It follows the Skia / Cairo / image/draw layering: a foundation below, many renderers on top. It depends on nothing fleet-side except go-asmgen for optional SIMD, and it cross-compiles to a static binary on every 64-bit target.

Packages

A single Go module, github.com/go-gfx/gfx, split into focused packages — import only what you need.

geometry

Points, rectangles and affine transforms — the coordinate math shared by every layer: translate, scale, rotate, shear, compose and invert.

color

Colour science: RGB / XYZ / Lab, sRGB↔linear conversion, premultiplied alpha, and Porter-Duff / separable blend modes done correctly in linear light.

raster

The shared pixel-buffer and pixel-format substrate — the common image surface every consumer reads and writes, with format conversions between them.

resample

High-quality resizing: box / area averaging, bicubic (Catmull-Rom) and Lanczos, separable and weight-precomputed, validated against reference implementations.

codec

Image decoders and encoders — PNG, JPEG, WebP, ICO, ICNS, GIF, TIFF — one shared set that subsumes the codecs each consumer used to hand-roll. Hardened decoders: Netpbm and QOI headers are checked against the file before any allocation (v0.36.2), and ICO is decoded in-house, bounded and with Chromium's alpha rule (v0.36.3).

vector

Paths, an anti-aliased scanline rasterizer, strokes and gradients — the 2D vector engine renderers build on instead of rolling their own. Since v0.40.0 it also carries ParseData, the path-data parser: SVG’s d, ODF’s svg:d and OpenXPS’s abbreviated geometry are one syntax (ECMA-388 Annex C), read once here rather than transcribed by each format.

svg

An SVG rasterizer and walker. Since v0.41.0 the opacity attribute is honoured as SVG group opacity: the element or group is drawn offscreen and blended once (SVG 1.1 §14.5), so overlapping children no longer show through each other.

WebGPU in the browser

A second module, github.com/go-gfx/webgpu: the GPU layer for Go programs built with GOOS=js. Released: v0.15.0.

webgpu

A typed API over the browser's WebGPU: devices, buffers, textures, pipelines, render bundles, OffscreenCanvas surfaces. Out-of-range writes are errors at the call, and quotas let an embedder run untrusted code.

Batched encoding

A whole submit recorded in Go and replayed with one JavaScript call: about six times fewer CPU microseconds per frame than one call per draw. The stream format is a portable package (wire), so another process can check a stream and remap its object ids before replaying it. Outside the browser, a remote device sends the same API's work (descriptors and streams) to a device that runs it. For example, a VM guest's program runs on the browser's GPU through go-virtio/gpudev.

Read-back and the host context

Since v0.7.0 a stream can read a GPU buffer back: Recorder.ReadBuffer (opcode 34, stream version 4) returns a bounded window with the submit, at about 124 µs for 4 KiB and 155 µs for 1 MiB on Apple Metal. The new batch package is the transport-free host side of a stream: private guest ids, checked reads, one implementation for every transport.

Range checks on replay

Since v0.8.0 wire.CheckRanges refuses, before the backend or replay.js runs, a buffer write or copy outside its buffer, indirect arguments that leave the buffer, and a dispatch above maxComputeWorkgroupsPerDimension. Errors wrap wire.ErrRange, and the check is fuzzed.

wgsl

A pure-Go WGSL front end, github.com/go-gfx/wgsl: lexer, parser, printer (the output re-parses to an equal AST), name resolution and type checking. Reserved words such as meta are rejected with a line and column, and every input is bounded. Checked against the W3C WebGPU CTS validation cases; the wgsl check and wgsl fmt commands run it from a shell. Since v0.2.0 a loop-budget transform bounds every loop, for and while and sets a flag the host reads back when a run is cut; it does not depend on the checker, which is not yet a security boundary. Docs.

2D on the GPU

A third module, github.com/go-gfx/gpu2d: one backend-neutral list of instances, drawn by WebGPU in the browser or by a Metal compute kernel on a Mac, and held to a CPU reference that defines every pixel. Released: v0.3.0.

gpu2d

Fills and outlines, square or with anti-aliased rounded corners; glyph masks, scaled images and paths (since v0.2.0); under nested translations and clips. Rasterize, the CPU reference, equals go-widgets/painter's PixelPainter byte for byte over 3000 random scenes and 51,947 primitives.

13 to 32 times faster

A widget-toolkit frame on an Apple M4 Max: 13.1 ms at 1080p and 52.5 ms at 4K on PixelPainter; 0.99 ms and 1.62 ms with WebGPU in Chromium; 1.08 ms and 2.79 ms with the Metal kernel, binning included.

Asynchronous submit

Since v0.3.0 the Metal renderer has Submit and Wait, with two frames in flight, so the CPU records the next frame while the GPU draws this one: 3.17 ms per frame with Draw against 1.78 ms with 1.5 ms of CPU work, on go-macos/metal v0.4.0.

Exact on the GPU

The Metal kernel blends with the reference's integer arithmetic and differs on no channel of any pixel. WebGPU's fixed-function blending matches every channel over an opaque surface; over a translucent one alpha differs by up to 4, and the tests report it.

Consumers

go-gfx is a foundation: it is meant to be depended on. These fleet libraries build on it instead of each re-implementing the same primitives.

go-images

The scikit-image-style image-processing library. Filters, edges and morphology built on raster, color and resample.

go-widgets/painter

The tri-backend widget renderer. Path fills, strokes and gradients built on vector, raster and color.

go-webengine

The headless HTML/CSS → image engine (no Chromium). Layout painting built on resample, codec and vector.

go-widgets/desktop

The desktop shell. Icon and thumbnail rendering built on codec and resample, replacing hand-rolled ICNS/ICO decoders.

Quality bar

  • Pure Go. CGO_ENABLED=0 across the org. No Skia, no Cairo, no native shims.
  • Zero dependencies. Nothing fleet-side except go-asmgen for optional SIMD, pulled in only at code-generation time.
  • 100% test coverage. Gated in CI, including error branches, validated against reference implementations.
  • Six architectures. Build + test on all six of Go's 64-bit targets — amd64 / arm64 natively, loong64 / riscv64 / ppc64le / s390x under qemu.
  • BSD-3-Clause on every source file.
